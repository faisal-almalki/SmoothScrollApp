# Spike: هل يقدر Expo يسوي فيد فيديو مثل تيك توك؟

تجربة أسبوع واحد قبل قرار إعادة بناء التطبيق بـ React Native/Expo ليشتغل على
الآيفون والأندرويد من كود واحد.

**شاشة واحدة فقط:** فيد فيديو عمودي بسحبة كاملة لكل مقطع، فوقه بطاقة الإعلان
بالسعر والمدينة — قلب المنتج. لا تسجيل دخول ولا تنقّل ولا أي شي ثاني؛ أي
إضافة تلوّث القياس.

## طريقة التجربة (١٠ دقايق)

تحتاج: كمبيوتر عليه Node.js، وجوال.

```bash
cd spike-expo-feed
npm install
npx expo start
```

1. حمّل تطبيق **Expo Go** من متجر جوالك (App Store أو Google Play).
2. افتح Expo Go وصوّر رمز QR اللي طلع في الطرفية.
3. التطبيق يفتح على جوالك مباشرة. اسحب.

> الجوال والكمبيوتر لازم يكونون على نفس الشبكة. لو ما اشتغل جرّب
> `npx expo start --tunnel`.

## وش تقيّم بالضبط

اسحب بسرعة، اسحب ببطء، ارجع للخلف، اترك الفيديو يلف، اضغط للصوت. وقارن
بإحساس تيك توك الحقيقي:

- [ ] الفيديو التالي يبدأ فوراً عند السحب، أو فيه لحظة سوداء؟
- [ ] أثناء السحب نفسه، تشوف الفيديو الجاي ولا شاشة سوداء؟
- [ ] السحب السريع لخمس مقاطع ورا بعض — يتعثر؟
- [ ] الرجوع لمقطع سبق شفته — يكمل ولا يبدأ من الصفر؟
- [ ] على جوال أندرويد **رخيص** تحديداً — نفس الإحساس؟

لو الإجابات مرضية على أندرويد رخيص، القرار: أعد البناء بـ Expo.
لو لا، القرار: كمّل بالتطبيق الأصلي وابنِ نسخة آيفون منفصلة لاحقاً.
خسارتك في الحالتين: أسبوع واحد.

## كيف مبني

نفس فكرة طبقة Media3 في تطبيق الكوتلن، بس بثلاث لاعبات بدل واحد لكل صف:

- **حوض ثلاث لاعبات** (السابق/الحالي/التالي) يُعاد استخدامها بالتناوب —
  إنشاء اللاعب هو الجزء الغالي على المنصتين.
- **الجيران محمّلين مسبقاً**: اللاعب الجار واقف مؤقتاً والمصدر متصل، يعني
  يبفّر قبل ما يوصل الشاشة. هذي هي خدعة "يبدأ فوراً".
- كل صف معروض يركّب عرض لاعبه حتى لو مو نشط، عشان أثناء السحبة تشوف
  الإطار الأول للفيديو الجاي بدل سواد.

الفيديوهات من مخزن قوقل العام للعينات (مصدر تطبيق الكوتلن الأصلي مات —
مشروع الفايربيس حقه طاح من الخطة المجانية). البيانات في `src/catalog.ts`
مشكّلة بنفس شكل ردّ `GET /feed` من السيرفر الحقيقي، فالربط لاحقاً هو
استبدال ملف واحد بـ fetch.
